# Video CDN readiness checklist

This checklist maps the CDN streaming ideas from the Viblo article to the current LMS video stack.

Reference:

- https://viblo.asia/p/cdn-cho-video-streaming-kien-truc-phan-phoi-toi-uu-hieu-nang-va-kiem-soat-chi-phi-o-quy-mo-lon-8X4EjGYzJN2
- https://developers.cloudflare.com/r2/api/workers/workers-api-reference/

## 1. Current project fit

The project already follows the VOD CDN pattern:

1. Teachers upload video.
2. Backend ingests the upload into a private video asset.
3. Shaka/ffmpeg creates adaptive HLS/DASH packages.
4. Video packages are stored under `video-packages/{assetId}/...`.
5. Learners receive signed playback manifests.
6. Segment/object traffic can be moved from backend-mediated `/object` URLs to the media custom domain.
7. The Cloudflare Worker validates `verify=<timestamp>-<hmac>` before serving private R2 objects.

This means the right optimization target is not only more storage. The main target is to keep hot HLS/DASH segments at the edge and keep the backend as the control plane for auth, manifests, and lifecycle operations.

## 2. CDN delivery checks

Before treating media-domain delivery as production-ready, confirm:

- `/actuator/health` reports `targetStackReady=true`.
- `/actuator/health` reports `mediaDomainConfigured=true`.
- `/actuator/health` reports `edgeAuthConfigured=true`.
- `/actuator/health` reports `cdnSegmentDeliveryReady=true`.
- Manifest URLs still require LMS auth.
- Segment URLs use the media custom domain when `app.video.edge-auth-mode=media_hmac_query`.
- Unsigned segment requests return `403`.
- Signed segment requests return `200`.
- Repeated signed full-object requests expose `X-Edge-Cache: MISS` then `X-Edge-Cache: HIT`.
- `Range` requests return `206` and `Content-Range`; these should bypass Worker Cache API to avoid poisoning the full-object cache.

Useful smoke commands:

```bash
curl -I "https://media.example.com/video-packages/{assetId}/segments/standard/init.mp4"
curl -I "https://media.example.com/video-packages/{assetId}/segments/standard/init.mp4?verify={token}"
curl -I "https://media.example.com/video-packages/{assetId}/segments/standard/init.mp4?verify={token}"
curl -I -H "Range: bytes=0-1023" "https://media.example.com/video-packages/{assetId}/segments/standard/init.mp4?verify={token}"
```

Expected results:

- no token: `403`
- first signed full-object request: `200`, `Cache-Control: public, max-age=31536000, immutable`, `X-Edge-Cache: MISS`
- second signed full-object request: `200`, `X-Edge-Cache: HIT`
- signed range request: `206`, `Content-Range`, `X-Edge-Cache: MISS`

## 3. Cache policy

Use different cache behavior by object type:

- HLS/DASH segments and init fragments: long immutable TTL.
- Package manifests generated by backend: short TTL, because they contain signed segment URLs.
- Authorization failures: do not cache.
- Missing objects: do not cache until the packaging pipeline is proven stable.
- Backend API responses: do not cache unless explicitly designed for it.

The Worker cache key should ignore `verify` only after the token is validated. This keeps tokenized access control while allowing learners with different signed URLs to share the same cached segment.

## 4. Cost and storage controls

When R2 free storage is tight, prioritize these controls before rotating accounts:

- Keep checksum dedupe enabled so identical uploads reuse one canonical package.
- Keep source retention configurable; after packaging succeeds, source files can be deleted when policy allows it.
- Use the orphan cleanup report before deleting any package prefix.
- Track package size by rendition profile so the default offline profiles do not overproduce variants.
- Keep YouTube metadata embeds for videos that are allowed to play externally.
- Mirror only videos the school owns or is licensed to store offline.

Account rotation can work temporarily, but it creates operational risk: fragmented credentials, harder lifecycle cleanup, harder incident response, and more places where a course can point to a stale bucket. Prefer one governed bucket path first; add paid storage or a second supported provider only when reporting shows real sustained growth.

## 5. Vietnam learner performance

For a Vietnam-heavy learner base:

- Enable HTTP/3/QUIC on the media domain when available.
- Watch Cloudflare cache hit ratio and origin R2 reads.
- Compare latency from at least two networks, not only the server VM.
- Keep HLS/DASH segment delivery off the backend path during peak tests.
- Consider a domestic CDN or multi-CDN only after Cloudflare edge hit ratio is healthy but regional latency is still too high.

## 6. Review gate

Do not mark the PR ready until:

- backend targeted tests pass
- `git diff --check` passes
- Worker deployment smoke confirms signed media requests
- a teammate reviews the storage deletion/orphan cleanup behavior
- a teammate reviews whether source deletion policy is acceptable for the school
